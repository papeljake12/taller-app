# T01. Talleres y usuarias

## Qué hace ahora la aplicación

- Existen los **talleres** y las **usuarias**. Cada usuaria pertenece a un taller y es dueña o
  costurera. Tu usuario de administrador no pertenece a ningún taller.
- En el **panel de administración** (`/admin/`) puedes crear talleres (con nombre, teléfono y
  logo) y usuarias para cada taller.
- Hay una página para **entrar** (`/entrar/`) con usuario y contraseña, y una forma de
  **salir** (`/salir/`).
- **Sin sesión, cualquier pantalla lleva a "Entrar".** Después de entrar, vuelve a la
  pantalla que se quería abrir, o a Hoy.
- **Bloqueo por intentos fallidos:** después de 5 intentos seguidos con la contraseña
  equivocada, ese usuario queda bloqueado en ese equipo por 15 minutos.
- **La sesión se cierra sola** después de 7 días sin usar la aplicación.

La página para entrar todavía se ve sin diseño, como texto plano. En T02 queda como una
tarjeta centrada sobre el marco negro.

## Librerías instaladas

- **django-axes**: cuenta los intentos fallidos y bloquea. Estaba en el stack.
- **Pillow**: Django la necesita para cualquier campo de imagen (el logo del taller). Más
  adelante también sirve para reducir el tamaño de las fotos de los pedidos (T13). La
  aprobaste antes de empezar.

## Qué se probó

`uv run pytest`: 45 pruebas, todas pasan. Entre ellas:

- Con datos correctos entra a Hoy.
- Con usuario o contraseña equivocados muestra el mismo mensaje, sin decir cuál de los dos falló.
- Una usuaria desactivada no puede entrar.
- Con 4 intentos fallidos todavía puede entrar. Con 5, queda bloqueada aunque después ponga
  la contraseña correcta.
- El bloqueo es solo para ese usuario en ese equipo: otra usuaria en el mismo equipo sí
  entra, y la misma usuaria desde otro equipo también.
- Sin sesión, la pantalla Hoy lleva a "Entrar".
- Después de entrar no se puede redirigir a otro sitio de internet (protección contra
  enlaces tramposos).
- Salir cierra la sesión, y solo funciona con un botón, no con un enlace.
- En el panel se crean talleres y usuarias. Un logo que no es imagen se rechaza. No se puede
  crear ni dejar a una dueña o costurera sin taller.
- No faltan migraciones por crear.

También se aplicaron las migraciones en tu base de datos `taller`.

## Decisiones y por qué

- **Usuario propio desde la primera migración.** Así lo pide el modelo de datos: cambiarlo
  después obliga a rehacer la base.
- **La regla "sin sesión no se entra" es para toda la aplicación**, no pantalla por pantalla.
  Una pantalla nueva queda protegida aunque alguien olvide marcarla. Las que deben ser
  públicas (como el formulario de tallas, T11) se marcan una por una.
- **El bloqueo se aplica a la pareja usuario + equipo.** Si fuera solo por equipo, una
  costurera que se equivoca bloquearía a todas las del taller, porque comparten el mismo
  internet. Si fuera solo por usuario, cualquiera podría bloquear a la dueña desde afuera
  escribiendo mal su clave a propósito.
- **Si alguien sigue intentando durante el bloqueo, la espera vuelve a empezar.** Es lo que
  hace django-axes por defecto y la página de bloqueo lo avisa. Para desbloquear antes de
  tiempo: `uv run python manage.py axes_reset`.
- **Un taller con usuarias no se puede borrar.** Para no perder datos por un clic
  equivocado. Para "sacar" a alguien se desactiva su usuario; sus registros se conservan.
- **El rol por defecto es costurera**, que es el que menos puede hacer. Ser dueña se elige a
  propósito.
- **La base de datos también exige el taller.** Además del formulario, la tabla tiene una
  regla: un usuario que no es administrador debe tener taller. Así no puede quedar una
  usuaria suelta ni por un error del código.
