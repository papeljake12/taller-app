# T00. Preparar el proyecto

## Qué hace ahora la aplicación

Ya existe un proyecto Django que arranca. Al abrir http://127.0.0.1:8000 aparece una página
muy sencilla que dice "Hoy" y la fecha. Todavía no tiene el diseño: eso llega en T02.

## Qué archivos cambiaron y para qué sirve cada uno

| Archivo | Para qué sirve |
|---|---|
| `pyproject.toml` | La lista de librerías que usa el proyecto y la versión de Python (3.12). |
| `uv.lock` | Las versiones exactas de cada librería, para que en todos los equipos se instale lo mismo. |
| `.python-version` | Le dice a `uv` que use Python 3.12. |
| `manage.py` | La herramienta de Django para correr el servidor, crear tablas, etc. |
| `config/settings/base.py` | Los ajustes comunes: idioma, zona horaria, base de datos, aplicaciones. |
| `config/settings/local.py` | Los ajustes de tu computador. Es el que usa `runserver`. |
| `config/settings/pruebas.py` | Los ajustes que usan las pruebas automáticas. |
| `config/entorno.py` | Lee el archivo `.env`, donde están las claves. |
| `config/urls.py` | Las direcciones principales del proyecto. |
| `config/wsgi.py` | La puerta de entrada que usará el servidor en internet (se completa en T24). |
| `pedidos/` | La app de pedidos. Por ahora solo tiene la pantalla Hoy, vacía. |
| `tests/test_humo.py` | La "prueba de humo": comprueba que la página de inicio responde, que la base de datos es PostgreSQL y responde, y que el idioma y la hora son los de Colombia. |
| `tests/test_entorno.py` | Pruebas del lector del archivo `.env`. |
| `CLAUDE.md` y `README.md` | Se completó la sección de comandos y cómo correr el proyecto. |

## Librerías instaladas

- **Django 5.2**: el marco con el que se construye la aplicación. Es la versión de soporte largo.
- **psycopg**: el conector que le permite a Django hablar con PostgreSQL.
- **pytest y pytest-django**: para escribir y correr las pruebas automáticas. Solo se usan
  en desarrollo; no van al servidor.

## Qué se probó

- `uv run pytest`: 11 pruebas, todas pasan.
- `uv run python manage.py check`: sin problemas.
- Se encendió el servidor y la página de inicio respondió con "Hoy" y la fecha.

## Qué no se probó

- No se creó ninguna tabla en tu base de datos `taller`. Fue a propósito: la primera
  migración debe traer el usuario propio del proyecto (T01). Si se crean antes las tablas de
  usuarios normales de Django, después no se pueden cambiar sin borrar la base.

## Decisiones y por qué

- **Ajustes por entorno.** Hay un archivo de ajustes para tu computador y otro para las
  pruebas. En T24 se agrega el del servidor. Así cada lugar tiene lo suyo sin mezclar.
- **El `.env` se lee con un código propio y corto** (`config/entorno.py`) en vez de instalar
  una librería para eso. Hace lo necesario: ignora comentarios, quita comillas y deja que una variable
  del sistema gane sobre la del archivo (útil en el servidor).
- **Si falta una clave obligatoria**, la aplicación no arranca y dice cuál falta, en vez de
  arrancar con un valor inventado.
- **Las pruebas usan su propia base temporal** (`test_taller`), que se crea y se borra sola.
  Por eso el usuario `taller` de PostgreSQL necesita el permiso `CREATEDB`.
- **Fechas.** Django en español de Colombia escribe los meses con mayúscula ("Noviembre").
  El diseño usa minúscula ("11 de noviembre"), como manda la ortografía. Por ahora la página
  muestra lo que da Django; en T02 se agrega un filtro propio para que la fecha quede como en
  el diseño.
- **La página Hoy vive desde ya en `pedidos/vistas/hoy.py`**, que es donde va a quedar según
  el plan. Así no hay que moverla después.
