# T03. Aislamiento entre talleres

## Qué hace ahora la aplicación

Para la usuaria no cambia nada visible. Por dentro, queda **una sola forma** de leer datos de
un taller, y esa forma siempre filtra por el taller de quien inició sesión. Así, cuando en
las tandas siguientes lleguen pedidos, clientes, telas y gastos, una usuaria nunca podrá ver
los de otro taller, ni siquiera cambiando el número en la dirección.

Además:

- Cada vez que alguien abre una pantalla, la aplicación ya sabe de qué taller es
  (`request.taller`), sin tener que buscarlo en cada vista.
- Si tú (el administrador, que no tienes taller) abres una pantalla de la aplicación, te
  lleva al panel de administración en vez de mostrarte pantallas vacías.

## Qué archivos cambiaron y para qué sirve cada uno

| Archivo | Para qué sirve |
|---|---|
| `cuentas/aislamiento.py` | La forma única de filtrar por taller. Arriba tiene ejemplos de cómo usarla. |
| `cuentas/models.py` | Las usuarias ya se pueden filtrar por taller (`Usuario.objects.del_taller(taller)`). |
| `cuentas/vistas.py` | "Salir" también funciona para el administrador. |
| `config/settings/base.py` | Se agregó el paso que deja a mano el taller en cada petición. |
| `tests/test_aislamiento.py` | La prueba con dos talleres. Es la plantilla para las tareas siguientes. |
| `tests/urls_aislamiento.py` | Dos pantallas de prueba (una lista y un detalle) que usan la forma única, solo para las pruebas. |

## Cómo se usa (para las tareas siguientes)

- Un modelo que pertenece a un taller hereda de `ModeloDeTaller`. Eso le da el campo
  `taller` y la consulta `.del_taller(taller)`.
- Un modelo que cuelga de otro (un abono cuelga de su pedido) dice por dónde llegar al
  taller: `ruta_taller = "pedido__taller"`.
- En una vista: `del_taller(request, Pedido)` para listas y `obtener_o_404(request, Pedido,
  pk=pk)` para abrir uno. Si es de otro taller, responde "no encontrado" (404).
- El taller de un registro nuevo lo pone la vista con `request.taller`. Nunca llega del
  formulario: el campo ni siquiera aparece en los formularios.

## Qué se probó

`uv run pytest`: 55 pruebas, todas pasan. Las nuevas:

- Con dos talleres, cada uno ve solo lo suyo.
- Sin taller no se ve nada.
- Pedir algo del otro taller responde 404, igual que pedir algo que no existe. Así no se
  revela que existe.
- De punta a punta, con pantallas de prueba: la lista no muestra lo del otro taller y abrir
  por la dirección algo del otro taller responde 404.
- El administrador va al panel y puede salir.
- **Solo dos pantallas se abren sin sesión:** "Entrar" y la entrada del panel de
  administración. Si alguien agrega otra pantalla pública sin querer, esta prueba falla.

Para comprobar que las pruebas sirven, se rompió el filtro a propósito: 5 pruebas fallaron.
Después se dejó como estaba.

## Qué no se probó

- Por ahora el único dato que pertenece a un taller son sus usuarias, así que la prueba
  corre solo con ellas. En la tanda 2, cada modelo nuevo se agrega a la lista
  `MODELOS_DE_TALLER` de `tests/test_aislamiento.py` y las mismas pruebas corren para él.

## Decisiones y por qué

- **Una sola forma, en un solo archivo.** Si cada pantalla filtrara a su manera, bastaría
  con que una se equivocara para mostrar datos ajenos. Con una sola forma, se revisa una vez.
- **Sin taller no se ve nada (en vez de verlo todo).** Si algo falla y no se sabe el taller,
  lo seguro es no mostrar nada.
- **404 y no "sin permiso".** Así quien prueba números en la dirección no puede saber qué
  existe en otros talleres.
- **El taller nunca llega del formulario.** Aunque alguien modifique a mano lo que envía el
  navegador, no puede guardar algo en otro taller.
